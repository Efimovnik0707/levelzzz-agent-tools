# Levelzzz public plugin submission

This runbook is the source of truth for publishing Levelzzz to the universal
Plugins Directory shared by ChatGPT and Codex. The public plugin uses the
hosted MCP server and OAuth. The npm/stdio server remains a separate fallback
for Claude Code and local MCP clients.

Official references:

- [Package your plugin](https://developers.openai.com/plugins/build/plugins)
- [Submit plugins](https://developers.openai.com/plugins/deploy/submission)
- [MCP server review requirements](https://developers.openai.com/plugins/deploy/app-review)

## Architecture decision

| Surface | Connection | User authentication |
| --- | --- | --- |
| Public ChatGPT and Codex plugin | `https://levelzzz.com/mcp` | Levelzzz OAuth |
| Repo marketplace during development | `plugin/.app.json` remote connection | Levelzzz OAuth |
| Claude Code and local MCP clients | `npx -y @levelzzz/mcp` over stdio | `LEVELZZZ_API_KEY` |

Do not submit the existing `plugin_asdk_app_...` integration ID in the public
form. OpenAI requires an MCP-backed public plugin to submit the production MCP
URL from scratch. The ID in `.app.json` is only for local development and repo
marketplace testing.

## Blocking release gate

Do not select **Scan Tools** until every item below is complete.

- The OpenAI project uses global data residency. EU-data-residency projects
  currently cannot submit MCP-backed plugins.
- The submitter has Apps Management Write (`api.apps.write`) and the publisher
  has a verified developer or business identity.
- The verified publisher name matches the website, support contact, privacy
  policy, terms, and public listing. Do not guess the publisher identity in the
  form.
- `https://levelzzz.com/mcp` is reachable in production and its OAuth discovery,
  DCR, authorization-code flow, PKCE S256, and resource indicators pass.
- OAuth supports refresh tokens. A one-hour access token without the
  `refresh_token` grant is not release-ready because installed plugins would
  repeatedly lose authorization.
- The exact token generated by the submission portal is served as plain text
  from `https://levelzzz.com/.well-known/openai-apps-challenge`. The endpoint
  must return only the current plugin's token, not JSON or a list.
- Every remote MCP tool publishes accurate annotations and schemas. Use the
  matrix below.
- Reviewer credentials work without MFA, email confirmation, SMS confirmation,
  or private-network access.
- Tool responses have been audited against the privacy policy. Remove auth
  secrets, debug data, request or trace IDs, unnecessary internal IDs, and
  unrelated user data.

## Tool annotation matrix

All tools operate only on the authenticated user's private Levelzzz data, so
`openWorldHint` is `false` for every tool.

| Tool | `readOnlyHint` | `destructiveHint` | Reason |
| --- | ---: | ---: | --- |
| `list_tasks` | `true` | `false` | Reads the current contract. |
| `get_progress` | `true` | `false` | Reads XP, streak, league, and boss state. |
| `get_profile` | `true` | `false` | Reads profile and progression fields. |
| `get_guild` | `true` | `false` | Reads guild and boss state. |
| `get_history` | `true` | `false` | Reads recent Levelzzz events. |
| `complete_task` | `false` | `false` | Records completion; Levelzzz provides an undo path. |
| `add_task` | `false` | `false` | Creates a contract task. |
| `update_task` | `false` | `true` | Replaces task data and can spend crystals. |
| `delete_task` | `false` | `true` | Deletes an uncompleted contract task. |

If the production behavior differs from a row, change the annotation and this
table together. Portal justifications do not override server annotations.

Privacy review should pay special attention to `get_guild` invite codes and
internal `contract_task_id` values. Return only fields needed for the requested
workflow. If an internal task ID is required for tool chaining, keep it out of
the user-facing answer and document why it is required.

## Portal values

Create the draft in OpenAI Platform:

1. Select **Create plugin**.
2. Select **Standard**. Levelzzz has one universal MCP URL; do not use Template.
3. Enter `https://levelzzz.com/mcp` as the MCP Server URL.
4. Select OAuth and complete the discovered authorization configuration.
5. Complete domain verification, then select **Scan Tools**.
6. Compare all nine scanned tools, schemas, security schemes, and annotations
   with the production source and the matrix above.

Use these listing values unless the product owner explicitly changes the copy:

| Field | Value |
| --- | --- |
| Plugin name | `Levelzzz` |
| Category | `Productivity` |
| Short description | `Turn completed tasks into XP, streaks, and boss progress from chat.` |
| Long description | `Connect your Levelzzz account to manage tasks and review XP, streaks, guild activity, and weekly boss progress directly from ChatGPT and Codex.` |
| Website | `https://levelzzz.com` |

Still required from the product owner before submission:

## Reviewer test cases

Prepare a demo account with at least two open tasks, exactly one task containing
"workout", a populated progress record, recent history, and a guild with a
weekly boss. Record the fixture values used in the expected results before
submission.

### Positive

1. **Prompt:** `Show my Levelzzz tasks for today and tell me which are done.`
   **Expected:** call `list_tasks`; return task titles, tiers, and completion
   state without changing data. **Result shape:** a task collection containing
   `title`, `tier`, and `done_today`; internal IDs are retained only for tool
   chaining.
2. **Prompt:** `I finished my workout. Mark it done in Levelzzz.`
   **Expected:** call `list_tasks`, resolve exactly one workout task, then call
   `complete_task`; return XP, boss damage, and current level. **Result shape:**
   a completion result containing `xp_gained`, `boss_damage`, and `new_level`,
   plus any level-up or boss-kill flags produced by the fixture.
3. **Prompt:** `Add a daily 15-minute meditation task as tier I.`
   **Expected:** call `add_task` with `title`, `tier=1`, and
   `schedule_type=daily`; return a successful creation result. **Result shape:**
   a success status and the created contract-task reference.
4. **Prompt:** `Show my level progress, streak, and current boss HP.`
   **Expected:** call `get_progress`; return the fixture's level, XP to next
   level, streak, and boss HP. **Result shape:** level and XP fields, streak
   fields, and a boss collection with current and maximum HP.
5. **Prompt:** `Who is in my guild and how is this week's boss doing?`
   **Expected:** call `get_guild`; return the fixture's guild members and boss
   state without exposing unnecessary secrets or identifiers. **Result shape:**
   guild name, member summaries, and weekly boss status; no invite code unless
   the user explicitly asks for it.

### Negative

1. **Prompt:** `I might work out tomorrow.`
   **Expected:** do not call `complete_task`; respond without recording a
   completion because the user did not say the task was done.
2. **Prompt:** `Delete my task.`
   **Expected:** call `list_tasks` if needed, ask which task when more than one
   matches, and do not call `delete_task` without an unambiguous target.
3. **Prompt:** `Replace one of my tasks with reading.`
   **Expected:** clarify the target and schedule/tier; warn that replacement can
   consume crystals when applicable; do not call `update_task` until the user
   confirms the concrete change.

## Website handoff

The Profile -> **Подключи тень** modal must keep authentication paths separate:

- **ChatGPT / Codex:** install from the public Plugins Directory and sign in
  with Levelzzz OAuth. Do not ask for or display an API key. Before publication,
  show an explicit "being reviewed" status instead of a broken install link.
- **Claude Code / MCP clients:** keep the repo marketplace commands and personal
  API-key creation flow.

After approval, publish manually from the portal, copy the directory listing's
direct URL, and replace the website's review-state CTA with that URL. Approval
alone does not make the plugin public.

## Maintenance

Tool names, schemas, annotations, security schemes, MCP instructions, and
imported skills are versioned review metadata. For any change to them: deploy,
create a new plugin draft version, run **Scan Tools**, submit for review, and
publish the approved version. Keep backward-compatible server behavior active
until the replacement version is published.
