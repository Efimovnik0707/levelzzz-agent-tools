# Levelzzz Tracker

Использовать MCP `levelzzz`: `list_tasks`, `complete_task`, `add_task`,
`delete_task`, `update_task`, `get_progress`, `get_profile`, `get_guild`,
`get_history`.

## Безопасные действия

- Перед изменением получить свежие данные через `list_tasks`.
- Вызывать `complete_task` только после явного сообщения пользователя, что
  задача выполнена, и только при одном однозначном незакрытом кандидате.
  Детали передать кратким `proof_text`.
- При нуле или нескольких совпадениях не гадать: перечислить варианты и
  запросить уточнение.
- Вызывать `add_task`, `update_task` и `delete_task` только по прямой
  просьбе пользователя. Не делать фоновых мутаций по косвенным признакам.
- Не повторять уже выполненную задачу и не создавать дубликаты.
- При 429 ничего не ретраить вручную: MCP ждёт `Retry-After` и повторяет
  запрос один раз.

## Типы задач и расписания

Для кастомной задачи использовать:

- `oneshot` — разовая задача, одно выполнение;
- `weekly_n` — повторяемая задача, `schedule_count` от 1 до 7.

`daily` остаётся расписанием каталожных пресетов и старых клиентов. Новая
кастомная `daily` сервером нормализуется в `weekly_n`; без явно заданного
счётчика — в 7 раз за неделю.

Ориентир по тирам:

- I — лёгкая задача на 5–15 минут;
- II — основная задача на 30–60 минут;
- III — ключевая или тяжёлая задача на 90+ минут.

Для полного зачёта тира III нужен содержательный пруф минимум из 20
непробельных символов. Без него XP и урон начисляются как за тир II.

## Ограничения недельного плана

- Не более 21 строки контракта за неделю, включая уже израсходованные
  soft-removed строки.
- Бюджет объявленного объёма — 6300: стоимость тира I/II/III равна
  50/150/400 × число выполнений (`oneshot` = 1, `weekly_n` = N,
  `daily` = 7).
- Среди активных повторяемых задач допускается не более четырёх задач тира II
  и двух задач тира III. Разовые задачи не входят в эти tier-cap, но расходуют
  общий бюджет.
- Если точный остаток неизвестен, не обещать добавление: передать запрос
  серверу и честно пересказать его ответ.

## XP, стрик и сверх плана

Базовый XP тиров I/II/III: 10/25/50. Множитель стрика: ×1.0 для 0–2 дней,
×1.1 для 3–6, ×1.25 для 7–13, ×1.4 для 14–29 и ×1.5 для 30+ дней. Первое
действие дня даёт +10 XP; дневной потолок XP задач — 150. Самое первое
выполнение аккаунта даёт отдельный бонус +250 XP вне дневного потолка.

После исчерпания цели `weekly_n` режим «сверх плана» даёт половину
фактически доступного XP, не наносит урон боссу и не идёт в лигу или дневное
комбо. Текущая версия MCP не экспонирует параметр `over_plan`: не пытаться
передавать его и объяснить ограничение пользователю.

Не вычислять награду для ответа самостоятельно. После `complete_task`
показывать фактические XP, урон, уровень и стрик из результата MCP.

## Чтение данных

- Задачи — `list_tasks`.
- Прогресс, XP, стрик и боссы — `get_progress`.
- Профиль — `get_profile`.
- Гильдия — `get_guild`.
- История — `get_history` (`limit` максимум 50).

Пересказывать данные коротко, конкретными цифрами, ничего не выдумывать.

## Периодическая проверка

Если пользователь хочет регулярную проверку, объяснить, как настроить
периодический запуск в его клиенте или планировщике. Сначала уточнить удобное
расписание, часовой пояс и желаемый источник контекста; не предполагать
заранее конкретный процесс.

По умолчанию сделать такую проверку read-only: вызвать `list_tasks` и
`get_progress`, показать незакрытые задачи и предложить пользователю
подтвердить изменения в интерактивном диалоге. Не выполнять автоматическое
закрытие или другие мутации без свежего явного подтверждения пользователя.
